# Audit

## 2026-10-07 — Version 2.1.1 reliability audit

The review reproduced a broken recovery helper when its destination was a directory and confirmed that the upstream main bootstrap can return zero after `setup.sh` fails. Both are fixed. Earlier sections below describe historical behavior superseded by this release.

- **Installer status preserved:** [launcher template](lib/launcher.sh.in#L207) fetches main or the existing PR648 pin into a private checkout and invokes `setup.sh` directly. Main policy and the preview SHA are unchanged; the mutable wrapper and its destructive home-checkout cleanup are bypassed. Source: [upstream bootstrap](https://github.com/OpenVoiceOS/ovos-installer/blob/main/installer.sh#L59). [Failure tests](test/test_launcher.py#L808) cover both routes; [cleanup failure tests](test/test_launcher.py#L895) retain status23 even if source cleanup fails.
- **Safe activation and private backups:** [path checks](lib/launcher.sh.in#L175) refuse symlink/non-directory configuration parents and nonregular/symlink scenario/helper destinations. A FIFO cannot block copying; a directory cannot receive a nested helper. Checks repeat after fetching and before elevated activation. Backups and scenarios are0600; the checker is0700. [Storage tests](test/test_storage_hardening.py#L39) cover file, directory, FIFO and dangling/link variants without modifying unrelated destinations. Ordinary `.config` symlinks are deliberately refused and require an explicit user relocation before setup.
- **Concurrent handoffs serialized:** [per-account directory lock](lib/launcher.sh.in#L192) protects activation through installation and optional checks. A second launcher does not download or replace the active scenario/helper. Owned locks release on normal failure/cancellation; unknown existing locks are never deleted automatically. [Concurrent test](test/test_storage_hardening.py#L181) holds a fake install open while a second recipe is rejected. SIGKILL, power loss or forced reboot can leave an empty lock; all12 locale messages explain checking for active setup before removing that folder. [FAQ](FAQ.md#why-does-it-say-a-setup-is-already-running) gives recovery.
- **Cancelled preparation preserves recovery:** the new checker is staged until Bash and credential collection pass. [Cancellation/runtime tests](test/test_storage_hardening.py#L247) preserve the existing checker and scenario. INT/TERM/HUP traps and best-effort terminal restoration/cleanup retain the actual error status.
- **Bounded health probes:** [`run_bounded`](lib/runtime.sh#L10) limits service probes and audio dispatch, including Docker daemon hangs before Python starts. Its watchdog is canceled and reaped on completion/interruption. [`check_services`](lib/runtime.sh#L104) restricts Docker to running containers in the OVOS Compose project. Paused/restarting containers no longer imply health; [Docker status documentation](https://docs.docker.com/reference/cli/docker/container/ls/#status). [`sound_check`](lib/runtime.sh#L142) closes its MessageBus client even on exceptions. [Runtime regressions](test/test_runtime_hardening.py#L32) exercise failure, input forwarding, hung and TERM-ignoring workers, cancellation and transport errors.
- **Network hardening:** Git has no interactive credential prompt, aborts sustained transfers below1000bytes/s for30seconds and disables checkout hooks. This is a low-speed limit, not an end-to-end DNS/connect deadline. The wizard's initial curl now has a15-second connection timeout and120-second total timeout and still refuses partial failed downloads. Actual OVOS package/model downloads belong to the upstream installer.

Validation: **524 Python cases and38 Node tests passed**; full details are recorded in [maintenance](MAINTENANCE_REPORT.md). ShellCheck passes for generated launchers and runtime with only cosmetic SC1112 excluded; `sh -n`, reproducible generation and identical v1/v2 pass. Independent review also passed645 shell decoder/expiry checks and1,872 localized message round-trips across local sh, Bash POSIX and Zsh sh emulation. CI now tests Ubuntu and native macOS before Pages publication. No real installation or audio hardware test was performed. Public codes remain unsigned, editable data with local-clock one-hour freshness; this hardening does not create server-enforced expiry or protect against a malicious process controlling the same user account.

## 2026-10-07 — Version 2.1.0 wizard recovery audit

The terminal handoff now has four factual stages: device checks, downloading, installation, then verification. It does not infer working speech from a zero installer exit or running service. The private `~/.config/ovos-installer/check-setup.sh` is written and shown before installation can reboot. It never installs or downloads anything; status 0 means the user confirmed a spoken response, while status 3 means verification is incomplete or requires a satellite. The outer installer preserves its own result independently.

Evidence: **436 pytest cases and 38 Node tests pass**; `sh -n` and identical-entry-point checks pass. ShellCheck passes with the existing cosmetic Unicode-apostrophe warning SC1112 excluded. Tests use local fake network/privileged/service commands and real PTYs, not an actual installation.

- **Fixed blank-input dead ends:** [`read_field`](lib/runtime.sh#L28) retries only the current missing or malformed field. Earlier valid answers remain in memory. `:cancel`, EOF and signal traps retain the old scenario and restore terminal echo. Secrets remain masked through validation retries, including immediate pasted input. [`test_all_locales_retry_missing_credentials_without_losing_valid_url`](test/test_launcher.py#L682) verifies all 12 locales and both entry points.
- **Fixed weak endpoint syntax checks:** [`valid_url`](lib/runtime.sh#L6) rejects blank hosts, whitespace/control characters, unsupported schemes, embedded credentials, fragments and invalid port ranges. It accepts normal HTTP(S), local hosts and bracketed IPv6 forms without sending credentials or making a network validation call. [`test_url_syntax_is_validated_without_contacting_the_service`](test/test_launcher.py#L723) covers 21 positive/negative inputs. DNS, TLS, authentication and complete RFC edge-case validation remain upstream responsibilities.
- **Localized handoff:** All 50 launcher-owned messages exist in 12 catalogs. Checksum-verified recipe language applies to expiry errors. Corrupt/undecodable codes use the terminal environment language where recognized. Upstream installer output is outside this catalog and may still include English. Native-speaker approval has not been obtained, especially for Kabyle and Basque; catalog parity is not linguistic certification.
- **Honest verification:** [`check_services`](lib/runtime.sh#L58) checks the expected real systemd units, launchd jobs or OVOS Compose services. [`sound_check`](lib/runtime.sh#L94) optionally emits a localized sample through the installed OVOS MessageBus API, with bounded connection/playback waits and a 30-second Python alarm. A delivered message never counts as audible success; the user confirms hearing it and then an actual spoken reply. [`test_sound_check_uses_installed_bus_api_and_waits_for_human_confirmation`](test/test_launcher.py#L821) uses a fake local bus and proves that successful playback emission alone leaves verification incomplete.
- **Recovery retained:** [`test_durable_checker_is_private_read_only_and_honest_about_unverified_voice`](test/test_launcher.py#L763) verifies mode 0700, no installer invocation, running/waiting service cases and no fabricated completion. Failed installation preserves the checker and scenario backup; [`test_installer_failure_keeps_recovery_checker_and_never_reports_success`](test/test_launcher.py#L807) verifies no automatic reinstall.
- **Mac support pinned:** Current main documentation narrowed macOS support, while [the exact reviewed PR648 support contract](https://github.com/OpenVoiceOS/ovos-installer/blob/6ffd465028bac299e5235d619819bfdc734af073/docs/supported-systems.md) supports Intel and Apple Silicon. All Mac recipes now use this verified pin, including default speech. The default scenario still omits `speech_engine`. Other default-speech devices retain the upstream main bootstrap; its possible swallowed failure is why exit 0 is never described as successful installation.
- **Single-file bootstrap size checked:** [`build`](scripts/build-launcher.py#L11) embeds all catalogs once and writes only the chosen catalog into the private helper. [`test_generated_launchers_match_sources`](test/test_launcher.py#L797) checks parity, reproducibility and a 120,000-byte limit below Linux's per-argument 128-KiB ceiling for `sh -c`. The short bootstrap still refuses partially failed downloads.
- **Unchanged guards:** The 64-bit requirement, 3,600-second code deadline before side effects, fixed protocol enums, masked target-only secrets, literal forwarding and preview SHA verification remain covered by the complete regression suite.

Known limits: service running status is not readiness, verified audio hardware, installed-skill coverage or successful upgrades. Docker permission changes may require a new login. Audio dependencies may be unavailable and are reported as such. Custom configurations and server profiles require an appropriate installed skill or connected satellite. The first command is a suggested date/time skill exercise, not a guarantee of language support. Physical Pi/Mac/Windows installations and microphone/speaker acceptance remain outstanding. No browser status callback, inbound service, telemetry, log upload or fabricated completion was added.

## 2026-10-07 — Version 2.0.0 expiry audit (historical; 2.1.0 fixes endpoint feedback)

Evidence from the completed implementation checks: **38 Node tests and 350 pytest cases passed**, plus `sh -n` for both shell files and `cmp v1.sh v2.sh`. Tests never invoke real network installers. Manual review compared `scenario`, shell compatibility conditions and the timestamp decoder with the JavaScript contract. ShellCheck passed with existing cosmetic SC1112 excluded.

- **Verified code validation:** [codec.test.mjs](test/codec.test.mjs#L110) covers five golden vectors, every field value, reserved enum indexes, unsupported versions, all 496 single-character substitutions and all 80 single-bit changes. Python [test_frozen_vectors_match_python_javascript_and_shell](test/test_launcher.py#L290) compares independent reference bytes, Node codes and both shell decoders, including timestamps above 32-bit range.
- **Verified expiry before side effects:** [v2.sh lines 65–72](v2.sh#L65) validates CRC, version, clock, future dates and deadline before installer/configuration operations. [test_timestamp_boundaries_match_javascript_in_every_mode](test/test_launcher.py#L309) covers deadline minus one, exact deadline and deadline plus one in install, decode and scenario modes. [Clock tests](test/test_launcher.py#L353) cover malformed, failed and missing `date`; [state-preservation tests](test/test_launcher.py#L389) retain existing scenario contents.
- **Verified legacy refusal:** Both endpoints serve identical v2 checks. [test_legacy_codes_require_regeneration_before_any_effects](test/test_launcher.py#L335) verifies refusal of eight-character codes in every shell mode. [decodeRecipeEnvelope](codec.mjs#L123) permits legacy/expired choice recovery only with explicit boolean options; [recovery tests](test/codec.test.mjs#L246) retain other validation. These options do not exist in the shell interface.
- **Verified installation guards:** The Python tests use fake curl/git/sudo, reject 32-bit/root/wrong-OS/existing-checkout paths, preserve existing scenario data across failed downloads or SHA mismatches, and check backups, locale and feature flags.
- **Fixed during review:** `resolve_bash_runtime 4` now runs in a guarded substitution before scenario replacement. Tests cover a missing first candidate and unavailable Bash. This avoids premature `set -e` exits on Intel Mac Homebrew layouts.
- **Verified credential handling:** Real PTY tests feed literal metacharacters to Home Assistant and LLM prompts. Secrets are not echoed or interpreted as shell code.
- **Known inherited limitation:** The default upstream main bootstrap can return zero after setup.sh fails. The launcher deliberately prints no installation-success claim. Preview execution propagates setup status.
- **Known validation limit:** Integration endpoint validation checks an HTTP(S) prefix, not complete URL syntax or reachability. Malformed values may fail later in the installer. Quoted environment forwarding prevents shell evaluation.
- **Clock and authenticity limit:** [timestamp/currentTime](codec.mjs#L59) and the [target clock check](v2.sh#L68) validate representation, not trusted wall-clock accuracy. Browser/target skew may reject fresh codes; changing a clock or recomputing a public timestamp and CRC can bypass the intended age limit. This is an operational freshness check, not authorization. No signature, encryption, per-code server record, individual revocation or single-use protection is provided. Expiry is evaluated when the launcher starts, not as a timer that interrupts an accepted installation.
- **Trust boundary:** GitHub Pages supplies executable launcher code over HTTPS. CRC-8 only detects code transcription errors; it is not a signature. Codes contain known recipe values and an issuance timestamp, never scripts or arbitrary URLs. Replacing the public v1 endpoint does not alter copies of an older launcher already downloaded elsewhere.
- **Coverage limit:** Mock tests do not demonstrate real installation success, physical audio behavior, or native macOS execution. Real hardware acceptance remains outstanding.
